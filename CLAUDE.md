## Purpose

Static marketing website for **Laundry Day** — a Melbourne laundromat chain with 3 locations. This is a pure HTML/CSS/JS site with no framework, no build tools, and no Node.js dependency. It includes a 24-post SEO blog with scheduled date-gated publishing.

## When Working Here

This is a **zero-build static site**. Changes to HTML, CSS, or JS are live on the next Cloudflare Pages deploy. No `npm install`, no `pnpm build` — just edit and push.

- **Read first:** `README.md` (this project), `../CLAUDE.md` (workspace index)
- **Brain keywords:** `LaundryDay`, `laundryday.au`, `Laundry Day website`
- **Deploy after changes:** Push to main; Cloudflare Pages auto-deploys from the repo root

## Key Conventions

### DO NOT hand-edit these files
- `blog/index.html` — generated by `scripts/publish.py`
- `sitemap.xml` — generated by `scripts/publish.py`

If you make changes to blog listing logic or sitemap structure, modify `scripts/publish.py` instead.

### Blog metadata lives in posts.json

`blog/posts.json` is the single source of truth for the blog index. Each entry:
```json
{
  "slug": "how-to-wash-a-doona",
  "title": "How to Wash a Doona at a Laundromat",
  "date": "2026-03-02",
  "excerpt": "Your home machine can't fit a doona...",
  "alt": "How to wash a doona at a laundromat"
}
```

The `date` field controls when the post appears on the blog index. Posts with dates in the future are hidden until the daily GitHub Action runs.

### Blog post images

OG images for blog posts follow the naming convention: `assets/images/blog/{slug}.png`. Every post must have a matching image — the blog index template references `../assets/images/blog/{slug}.png`.

### Adding a new blog post

1. Write `blog/<slug>.html` — copy an existing post as a template
2. Add the entry to `blog/posts.json` with a future date
3. Create `assets/images/blog/<slug>.png` — use `/chatgpt-image` or `/nano-banana-pro`
4. Run `python3 scripts/publish.py` to verify the index and sitemap regenerate correctly
5. Commit all files; the post will go live automatically on its scheduled date

### CSS

All styles are in `css/styles.css` (versioned with `?v=N` query param for cache busting). The stylesheet uses CSS custom properties for the design system. When making CSS changes, **increment the version query parameter** in every HTML file that links to it (currently `?v=5` or `?v=6` depending on the page).

### JavaScript

`js/main.js` (versioned `?v=3`) handles:
- Mobile nav hamburger toggle with `aria-expanded`
- Smooth scroll for anchor links (with fixed header offset)
- Scroll-based bubble animations (intersection observer)

Inline `<script>` blocks in individual pages handle page-specific interactivity.

## GitHub Actions

The `scheduled-publish.yml` workflow runs daily at 7:00 AM AEST (UTC+11):
1. Checks out the repo
2. Runs `python3 scripts/publish.py`
3. If `blog/index.html` or `sitemap.xml` changed, commits and pushes

This is what "publishes" scheduled blog posts — no human intervention needed.

## Editing Guidelines

### Changing site-wide design
Edit `css/styles.css`. Increment the `?v=` query string on every HTML page's `<link>` tag to bust cache.

### Changing navigation or footer
Edit each HTML file individually — there are no includes or templates. The nav and footer are duplicated across all pages. Be thorough: update `index.html`, all 3 location pages, `privacy.html`, and the blog template in `scripts/publish.py` (it generates `blog/index.html` with its own inline nav/footer).

### Changing the blog index layout
Edit the `build_index()` function in `scripts/publish.py`. This function generates the full `blog/index.html` page. After editing, run the script and verify the output.

### Changing location details
Each location has its own HTML file (brunswick-east.html, st-albans.html, maribyrnong.html) and its own JSON-LD block in `index.html`. Update both the standalone page and the index page's structured data when details change.

## Known Issues

- Nav and footer are duplicated across ~30 HTML files (3 location pages + blog index + 24 blog posts). Template repetition is manual and error-prone. If major structural changes are needed, consider extracting a build step — but the current zero-build design is intentional for simplicity.
- The bubble animation fix (commit `cb27a46`) changed the CSS animation from a jittery zigzag to a smooth float. If bubble animations look wrong, check `css/styles.css` for the `@keyframes float` definitions.
- Cache busting is manual (`?v=N` on CSS/JS links). When you forget to increment, users may see stale styles until their cache expires.
